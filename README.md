# Jagire — AI-Powered Recruitment, Hiring & HR Operating System

Jagire is an **AI-powered Recruitment, Hiring, and HR Operating System** built with **React 19 + TypeScript + TanStack Router + React Query + Tailwind CSS v4 + Supabase**.

- **Job Seekers** get AI career tools — resume builder, ATS scoring, cover letter generation, interview practice, career coach, and career roadmaps.
- **Employers** get an enterprise-grade AI recruitment and HR platform — candidate matching, resume screening, smart ranking, interview scheduling, email automation, document generation, and a full AI office assistant.
- **Admins** get a full management panel for users, jobs, companies, blogs, support tickets, and content moderation.

Supports job seekers, employers, and admins with real-time messaging, interview scheduling, AI resume scoring, community feed, blogging, assessments, subscription management, and more.

## Tech Stack

- **Frontend**: React 19, TanStack Router (file-based), React Query, Tailwind CSS v4, shadcn/ui (New York), lucide-react icons
- **Backend**: Supabase (PostgreSQL, Auth, Realtime, Storage, Edge Functions)
- **AI**: Multi-provider fallback chain — Ollama (default) → Gemini → OpenRouter. See `docs/OLLAMA_AI.md` for setup.
- **Calendar**: Google Calendar API (OAuth) for interview scheduling with auto-generated Meet links
- **Email**: Resend via `send-email` Edge Function
- **Payments**: eSewa v2 (ePay) test mode with server-side verification
- **PDF**: html2pdf.js, jsPDF, @react-pdf/renderer
- **Document Extraction**: mammoth (DOCX), pdf-parse + unpdf (PDF), tesseract.js (OCR fallback)
- **Build**: Vite 8 + TanStack Start (SSR)

## Feature Flows

### 1. Authentication

**Files**: `src/routes/auth.tsx`, `src/hooks/use-auth.tsx`, `src/integrations/supabase/client.ts`

1. Sign up (email/password) or Google OAuth at `/auth`
2. `supabase.auth.signUp` → triggers `handle_new_user` DB trigger (creates `profiles` + `user_roles` row with default `job_seeker` role)
3. `onAuthStateChange` in `AuthProvider` updates session; role fetched from `user_roles` table (deferred to avoid deadlock)
4. Role drives dashboard redirect: `admin` → `/admin`, `employer` → `/employer`, else `/dashboard`
5. Referral codes captured via `?ref=` query param, stored in `referrals` table

### 2. Job CRUD (Employer)

**Files**: `src/routes/_authenticated/employer/jobs/new.tsx`, `src/routes/_authenticated/employer/jobs/$jobId.tsx`, `src/routes/_authenticated/employer/index.tsx`

1. Employer must have a company profile first (`/employer/company`)
2. Fill title, description, requirements, responsibilities, benefits, skills, location, salary, job type, experience level
3. Job created with `status: 'active'`, unique slug auto-generated
4. Redirect to `/employer/jobs/$jobId` (applicants page)
5. Employer dashboard (`/employer`) lists all jobs with applicant counts
6. Admin panel can activate/close any job

### 3. Application Workflow

**Files**: `src/components/apply-job-dialog.tsx`, `src/routes/_authenticated/employer/jobs/$jobId.tsx`, `src/routes/_authenticated/applications.tsx`, `src/lib/application-status.server.ts`

**Status Flow**:

```
applied → viewed → reviewing → shortlisted → interview → interview_scheduled → interview_completed → selected
                     ↓                                                          ↓
                  rejected                                                   offer
                     ↓
                  withdrawn
```

1. **Job seeker applies** (`ApplyJobDialog`): selects/uploads resume + cover letter → inserts `applications` row (`status: 'applied'`)
2. **Employer reviews** (`/employer/jobs/$jobId`): dropdown changes status via `updateApplicationStatus` server fn → updates `applications.status`, inserts `application_events` row, creates notification for seeker
3. **Job seeker tracks** (`/applications`): sees all applications with event timeline (each status change with timestamp)

### 4. Interview Workflow

**Files**: `src/components/schedule-interview-dialog.tsx`, `src/lib/google-calendar.service.ts`, `src/lib/connection-key-crypto.server.ts`

1. Employer clicks "Schedule" on applicant card → `ScheduleInterviewDialog` opens
2. Dialog checks Google Calendar connection (`getGoogleCalendarStatus` server fn)
3. If not connected: OAuth popup flow
   - `startGoogleCalendarConnect` → Google consent → `/google-calendar/callback` posts code to opener
   - `saveGoogleCalendarConnection` exchanges code for refresh token → AES-256-GCM encrypted → stored in `app_user_connections`
4. If connected: employer enters title, start time, duration
5. `scheduleInterview` server fn:
   - Refreshes access token via refresh token
   - Creates Google Calendar event with `conferenceData` (auto Meet link)
   - Sends email invite to candidate (`sendUpdates: all`)
   - Inserts `interview_events` row with `meet_link`, `google_event_id`
   - Meet link copied to clipboard
6. `rescheduleInterview` and `updateInterviewStatus` server fns handle changes
7. Candidate sees notification + interview on dashboard

### 5. AI Resume Scanner

**Files**: `src/routes/_authenticated/resume-scanner.tsx`, `src/lib/ai.service.ts` (`scanResumeFromStorage`), `src/lib/resume-extraction.ts`

1. Upload PDF/DOCX resume → stored in `resumes` Supabase Storage bucket
2. `scanResumeFromStorage` server fn:
   - Downloads file via service-role client
   - `extractResumeText` detects file type via magic bytes (%PDF, PK zip, OLE) then extracts text through a multi-stage pipeline:
     - **DOCX**: mammoth
     - **PDF**: pdf-parse → unpdf → OCR (tesseract.js, up to 5 pages at 2x scale) → raw text fallback
   - Validates extracted text is sufficient length and looks like a resume (keyword check)
   - Returns structured errors: `UNSUPPORTED_FILE_TYPE`, `FILE_PARSE_FAILED`, `INSUFFICIENT_TEXT`, `NOT_A_RESUME`
   - Calls AI with ATS-reviewer system prompt → returns JSON scores validated by `fullResumeScanSchema`
   - Updates `resumes` row with scores, suggestions, parsed data, and full career roadmap
3. Matches extracted skills against active jobs' `required_skills` → returns top 8 job matches with fit %
4. Auto-populates `profiles.skills` and `profiles.ai_profile_data` if user has no skills set

### 6. AI Career Recommendations

**Files**: `src/routes/_authenticated/career.tsx`, `src/lib/ai.service.ts` (`careerRecommendations`)

1. Server fn fetches user profile + default resume skills
2. AI returns JSON validated by `careerRecommendationsSchema`: career paths, skill gaps, recommended certifications, suggested search keywords
3. Rendered as cards with career paths, skill gap badges, cert list, search keyword chips

### 7. AI Learning Center

**Files**: `src/routes/_authenticated/learn.tsx`, `src/lib/ai.service.ts` (`learningRecommendations`)

1. Server fn uses profile skills + headline
2. AI suggests learning resources (courses, videos, challenges, interview prep) validated by `learningRecommendationsSchema`
3. Mark complete → inserts `learning_items` + `learning_progress` + awards badges
4. Progress bar + badge display

### 8. Profile Import (GitHub + LinkedIn)

**Files**: `src/routes/_authenticated/profile.tsx`, `src/lib/ai.service.ts`

**GitHub** (`importFromGitHub`): fetches GitHub user + starred repos via REST API → extracts projects, skills, updates profile

**LinkedIn** (`importFromLinkedInText`): user pastes LinkedIn text → AI extracts structured profile validated by `linkedinImportSchema` → updates profile

### 9. AI Career Coach

**Files**: `src/routes/_authenticated/career-coach.tsx`, `src/lib/ai.service.ts` (`careerCoach`)

- Chat-based AI career advisor
- Users ask career questions (skills to learn, rejection reasons, salary, career switching)
- AI returns structured JSON validated by `careerCoachResponseSchema`: advice, recommended skills, action plan, improvement suggestions, follow-up questions
- Conversation history saved per session in `career_coach_sessions` table
- Past sessions browsable in sidebar

### 10. AI Assistant (Career Companion)

**Files**: `src/routes/_authenticated/ai-assistant.tsx`, `src/components/ai-assistant-widget.tsx`, `src/lib/ai.service.ts` (`aiAssistantChat`)

A full ChatGPT-style AI career companion with RAG (Retrieval-Augmented Generation) context:

- Career coaching, resume assistance, job matching, interview preparation, salary advice (NPR context)
- RAG context retrieval: fetches user profile, resume analysis, applications, saved jobs, and active job listings
- Conversation memory: messages stored in `ai_conversations` + `ai_messages` tables
- Last 12 messages (6 turns) included as context for follow-up questions
- Full-page chat at `/ai-assistant` + floating assistant button on every authenticated page
- Markdown rendering, typing indicator, quick prompt buttons, mobile responsive

## AI Architecture

### Provider Fallback Chain

The AI service (`src/integrations/ai/ai-service.ts`) implements a multi-provider fallback chain:

| `AI_PROVIDER`  | 1st        | 2nd                     | 3rd                     |
| -------------- | ---------- | ----------------------- | ----------------------- |
| `ollama`       | Ollama     | Gemini (if key set)     | OpenRouter (if key set) |
| `gemini`       | Gemini     | OpenRouter (if key set) | Ollama                  |
| `openrouter`   | OpenRouter | Gemini (if key set)     | Ollama                  |

### Validation Pipeline

All AI JSON responses go through a validation pipeline:

1. **Response normalization** (`normalizeRawResponse`): recursively coerces numeric strings to numbers across all tasks
2. **Task-specific normalization**: resume-analysis, career-coach, and learning-recommendations get additional shape correction
3. **Zod schema validation**: each task has a dedicated schema with `.catch()` fallbacks on enums and `.coerce.number()` on numeric fields
4. **Retry with cache bypass**: if validation fails, retries with cache skipped (up to `VALIDATION_RETRY_LIMIT`)

### Model Assignment

| Model               | Purpose                              | Tasks                               |
| ------------------- | ------------------------------------ | ----------------------------------- |
| `qwen3`             | Main conversation model             | `career-assistant`, `career-coach`  |
| `mxbai-embed-large` | Semantic search / embeddings         | `embedding`                         |
| `llama3.2`          | Fast analysis & extraction           | `resume-analysis`, `job-matching`   |

Task-to-model mapping is in `src/integrations/ai/ollama-models.ts`. See `docs/OLLAMA_AI.md` for full setup instructions.

### Resume Extraction Pipeline

**File**: `src/lib/resume-extraction.ts`

1. **File type detection** via magic bytes: `%PDF` (PDF), `PK` (DOCX/zip), `D0CF11E0` (legacy DOC/OLE)
2. **DOCX extraction**: mammoth
3. **PDF extraction** (multi-stage fallback):
   - pdf-parse (primary)
   - unpdf (fallback)
   - OCR via tesseract.js (scanned PDFs, up to 5 pages at 2x scale)
   - Raw text regex (last resort, letter-only matches to avoid binary garbage)
4. **Quality gates**: minimum text length (50 chars) + resume keyword detection (experience, education, skills, etc.)
5. **Structured errors**: `UNSUPPORTED_FILE_TYPE`, `FILE_PARSE_FAILED`, `INSUFFICIENT_TEXT`, `NOT_A_RESUME`
