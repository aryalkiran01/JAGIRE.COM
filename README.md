# Jagire — AI-Powered Recruitment, Hiring & HR Operating System

Jagire is no longer just a job board. It is an **AI-powered Recruitment, Hiring, and HR Operating System** built with **React 19 + TypeScript + TanStack Router + React Query + Tailwind CSS v4 + Supabase**.

- **Job Seekers** get AI career tools — resume builder, ATS scoring, cover letter generation, interview practice, career coach, and career roadmaps.
- **Employers** get an enterprise-grade AI recruitment and HR platform — candidate matching, resume screening, smart ranking, interview scheduling, email automation, document generation, and a full AI office assistant.

Supports job seekers, employers, and admins with real-time messaging, interview scheduling, AI resume scoring, community feed, blogging, assessments, subscription management, and more.

## Tech Stack

- **Frontend**: React 19, TanStack Router (file-based), React Query, Tailwind CSS v4, shadcn/ui (New York), lucide-react icons
- **Backend**: Supabase (PostgreSQL, Auth, Realtime, Storage, Edge Functions)
- **AI**: Google Gemini (REST) for resume scoring, career recommendations, learning suggestions, LinkedIn/GitHub import
- **Calendar**: Google Calendar API (OAuth) for interview scheduling with auto-generated Meet links
- **Email**: Resend via `send-email` Edge Function
- **Payments**: eSewa v2 (ePay) test mode
- **PDF**: html2pdf.js, jsPDF
- **Build**: Vite 8 + TanStack Start (SSR)

## Feature Flows

### 1. Authentication

**File**: `src/routes/auth.tsx`, `src/hooks/use-auth.tsx`, `src/integrations/supabase/client.ts`

1. Sign up (email/password) or Google OAuth at `/auth`
2. `supabase.auth.signUp` → triggers `handle_new_user` DB trigger (creates `profiles` + `user_roles` row with default `job_seeker` role)
3. `onAuthStateChange` in `AuthProvider` updates session; role fetched from `user_roles` table (deferred to avoid deadlock)
4. Role drives dashboard redirect: `admin` → `/admin`, `employer` → `/employer`, else `/dashboard`
5. Referral codes captured via `?ref=` query param, stored in `referrals` table

### 2. Job CRUD (Employer)

**Files**: `src/routes/_authenticated.employer.jobs.new.tsx`, `src/routes/_authenticated.employer.jobs.$jobId.tsx`, `src/routes/_authenticated.employer.index.tsx`

**Create Job** (`/employer/jobs/new`):

1. Employer must have a company profile first (`/employer/company`)
2. Fill title, description, requirements, responsibilities, benefits, skills, location, salary, job type, experience level
3. Job created with `status: 'active'`, unique slug auto-generated
4. Redirect to `/employer/jobs/$jobId` (applicants page)

**Manage**:

- Employer dashboard (`/employer`) lists all jobs with applicant counts and views
- Job applicants page: change application status via dropdown, view resume (signed URL), message candidate, schedule interview
- Admin panel can activate/close any job

### 3. Application Workflow

**Files**: `src/components/apply-job-dialog.tsx`, `src/routes/_authenticated.employer.jobs.$jobId.tsx`, `src/routes/_authenticated.applications.tsx`

**Status Flow**:

```
applied → viewed → reviewing → shortlisted → interview → interview_scheduled → interview_completed → selected
                     ↓                                                          ↓
                  rejected                                                   offer
                     ↓
                  withdrawn
```

1. **Job seeker applies** (`ApplyJobDialog`): selects/ uploads resume + cover letter → inserts `applications` row (`status: 'applied'`)
2. **Employer reviews** (`/employer/jobs/$jobId`): dropdown changes status → updates `applications.status`, inserts `application_events` row, creates notification for seeker
3. **Job seeker tracks** (`/applications`): sees all applications with event timeline (each status change with timestamp)

### 4. Interview Workflow

**Files**: `src/components/schedule-interview-dialog.tsx`, `src/lib/google-calendar.functions.ts`, `src/lib/connection-key-crypto.server.ts`

1. Employer clicks "Schedule" on applicant card → `ScheduleInterviewDialog` opens
2. Dialog checks Google Calendar connection (`getGoogleCalendarStatus` server fn)
3. If not connected: OAuth popup flow
   - `startGoogleCalendarConnect` → Google consent → `/google-calendar/callback` posts code to opener
   - `saveGoogleCalendarConnection` exchanges code for refresh token → AES-256-GCM encrypted → stored in `app_user_connections`
4. If connected: employer enters title, start time, duration
5. `scheduleInterview` server fn:
   - Refreshes access token via refresh token
   - Creates Google Calendar event with `conferenceData` (auto Meet link)
   - Sends email invite to candidate (`sendUpdates: all`)
   - Inserts `interview_events` row with `meet_link`, `google_event_id`
   - Meet link copied to clipboard
6. Candidate sees notification + interview on dashboard

### 5. AI Resume Scanner

**Files**: `src/routes/_authenticated.resume-scanner.tsx`, `src/lib/ai.functions.ts`, `src/integrations/gemini/server.ts`

1. Upload PDF/DOCX resume → stored in `resumes` Supabase Storage bucket
2. `scanResumeFromStorage` server fn:
   - Downloads file via service-role client
   - Extracts text (mammoth for DOCX, unpdf for PDF)
   - Calls Gemini with ATS-reviewer system prompt → returns JSON scores
   - Updates `resumes` row with `overall_score`, `ats_score`, `grammar_score`, `formatting_score`, `keyword_score`, `professionalism_score`, `suggestions`, `parsed_data` (summary + skills)
3. Matches extracted skills against active jobs' `required_skills` → returns top 8 job matches with fit %
4. Results displayed with progress bars + suggestion list + job match cards

### 6. AI Career Recommendations

**Files**: `src/routes/_authenticated.career.tsx`, `src/lib/ai.functions.ts`

1. `careerRecommendations` server fn fetches user profile + default resume skills
2. Gemini returns JSON: `career_paths` (title, why, next_steps), `skill_gaps`, `recommended_certifications` (name, provider), `suggested_search_keywords`
3. Rendered as cards with career paths, skill gap badges, cert list, search keyword chips

### 7. AI Learning Center

**Files**: `src/routes/_authenticated.learn.tsx`, `src/lib/ai.functions.ts`

1. `learningRecommendations` server fn uses profile skills + headline
2. Gemini suggests 8 mixed resources (courses, videos, challenges, interview prep) with URLs, providers, skills
3. Mark complete → inserts `learning_items` + `learning_progress` + awards `badges`
4. Progress bar + badge display

### 8. Profile Import (GitHub + LinkedIn)

**Files**: `src/routes/_authenticated.profile.tsx`, `src/lib/ai.functions.ts`

**GitHub** (`importFromGitHub`): fetches GitHub user + starred repos via REST API → extracts projects (name, description, URL, stars, language), skills (unique languages), updates profile (full_name, bio, location, website, avatar)

**LinkedIn** (`importFromLinkedInText`): user pastes LinkedIn About/Experience text → Gemini extracts structured profile (full_name, headline, about, location, current_position, experience_years, skills) → updates profile

### 9. Real-Time Messaging

**Files**: `src/routes/_authenticated.messages.tsx`

1. Start: employer clicks message icon on applicant card → `/messages?with={userId}`
2. `useEffect` ensures chat exists (creates if needed, sorted `user_a`/`user_b`)
3. Left panel: chat list ordered by `last_message_at`
4. Right panel: message history, real-time via Supabase Realtime channel `chat:{id}` on `messages` INSERT
5. Send: insert into `messages`, update `chats.last_message_at`
6. Auto-scroll to bottom on new messages

### 10. Community Feed

**Files**: `src/routes/_authenticated.feed.tsx`

1. Create post: text + optional image upload (Supabase Storage `posts` bucket, 5MB limit, signed URL)
2. Feed: 50 posts ordered by `created_at DESC` with author info, likes/comments counts
3. Like: toggle in `post_likes` (optimistic via React Query invalidation)
4. Save: toggle in `post_saves`
5. comment: insert into `post_comments`
6. Realtime: channel `feed` on `posts` + `post_likes` changes → invalidates `feed` query
7. Share: native share API or clipboard fallback

### 11. Blog

**Files**: `src/routes/blog.index.tsx`, `src/routes/blog.$slug.tsx`, `src/routes/_authenticated.blog-editor.tsx`

- `/blog`: published posts only (RLS-enforced), cover image, tags, excerpt
- `/blog/$slug`: full post with cover, tags, publish date, markdown content
- `/blog-editor`: author CRUD (create, edit, delete, publish/draft toggle), slug auto-generated from title

### 12. Assessments

**Files**: `src/routes/_authenticated.assessments.tsx`

- Admin can create assessments (title, category, difficulty, description, questions as JSON, passing score, duration)
- Job seeker takes assessment: questions rendered without correct answers, radio selection
- Submit: client computes score (`correct/total * 100`), inserts `assessment_attempts` with answers + score
- Best score + pass/fail badge shown on assessment card

### 13. Admin Panel

**Files**: `src/routes/_authenticated.admin.tsx`

- Stats cards: users, jobs, applications, companies (exact count, head-only queries)
- Tabs: Users (list + role badges), Jobs (activate/close toggle), Companies (view link), Tickets (reply + resolve)
- Role guard: only `admin` role sees content; others see access-denied card

### 14. Notifications

**Files**: `src/routes/_authenticated.notifications.tsx`, `src/components/layout/site-header.tsx`

- Header bell shows unread count badge (query `notif-unread`)
- Realtime: channel `notif:{userId}` on `notifications` table → invalidates unread + list queries
- Notifications page: marks all as read on view, individual mark-read button
- Types: application, interview, message, assessment, admin, job, system

### 15. Companies & Reviews

**Files**: `src/routes/companies.index.tsx`, `src/routes/companies.$slug.tsx`

- Directory: all companies with logo, industry, tagline
- Detail: company info (mission, vision, culture, hiring process, benefits, technologies), open positions, reviews
- Reviews: star rating + title + body; company owner can reply (inserts `review_replies`)
- Average rating computed client-side

### 16. Resume Builder

**Files**: `src/routes/_authenticated.resume-builder.tsx`

- Multiple resumes per user (saved to `resumes.resume_data` JSONB)
- Sections: experience, education, skills, projects (add/remove items)
- Templates: modern, classic, minimal
- Live preview + PDF export via html2pdf.js (with oklch→hex color fix on clone)

### 17. Referrals

**Files**: `src/routes/_authenticated.referrals.tsx`

- Unique referral code on profile (DB trigger generates on signup)
- Shareable link: `/auth?ref={code}`
- Invite by email: inserts `referrals` row (status pending)
- Track referral status + reward credits

### 18. Payments & Subscriptions (eSewa)

- **eSewa v2 (ePay)** integration with server-side payment verification via the `verify-esewa-payment` edge function.
- Successful payments automatically activate the user's subscription (`subscriptions` table: `status=active`, `payment_status=paid`).
- **Admin subscription management** — admins can view all subscriptions (user, plan, status, start/end dates, amount, transaction ID, eSewa ref) and activate, extend, cancel, or change plans.
- **User subscription status** — logged-in users see their current plan, start date, expiry date, days remaining, and premium benefits on the Pricing page.
- **Navbar badge** — free users see an "Upgrade" button; premium users see a crown badge with plan name and days remaining.
- **Reusable `useSubscription` hook** — powers premium access checks across AI features, the pricing page, and the navbar.
- **Server-side premium gating** — all AI server functions call `requirePremium()` before executing; uses the service-role client so it cannot be spoofed from the frontend.

**Files**: `src/routes/checkout.$plan.tsx`, `src/routes/pricing.tsx`

- eSewa v2 ePay test mode (merchant `EPAYTEST`)
- HMAC-SHA256 signature over signed fields (total_amount, transaction_uuid, product_code)
- Plans: Starter (Rs. 4,900), Pro (Rs. 9,900)
- Success/failure redirect pages

### 19. AI Career Coach

**Files**: `src/routes/_authenticated/career-coach.tsx`, `src/lib/ai.service.ts` (`careerCoach` server fn)

- Chat-based AI career advisor using `qwen3` via Ollama
- Users ask career questions (skills to learn, rejection reasons, salary, career switching)
- AI returns structured JSON: advice, recommended skills, action plan, improvement suggestions, follow-up questions
- Conversation history saved per session in `career_coach_sessions` table
- Past sessions browsable in sidebar

### 20. AI Assistant (Career Companion)

**Files**: `src/routes/_authenticated/ai-assistant.tsx`, `src/components/ai-assistant-widget.tsx`, `src/lib/ai.service.ts` (`aiAssistantChat` server fn)

A full ChatGPT-style AI career companion with RAG (Retrieval-Augmented Generation) context:

**Capabilities**:

- Career coaching (skills to learn, rejection analysis, career paths)
- Resume assistance (improvement tips, ATS score explanation, missing skills)
- Job matching (find suitable jobs, explain job fit, required skills)
- Interview preparation (practice questions, answer feedback, technical roadmap)
- Salary advice (NPR context, offer evaluation — always Rs. format, never USD)

**Architecture**:

- Uses `career-assistant` AI task with `qwen3` as default model
- RAG context retrieval: fetches user profile, resume analysis, applications, saved jobs, and active job listings before generating each response
- Conversation memory: messages stored in `ai_conversations` + `ai_messages` tables with full history
- Last 12 messages (6 turns) included as context for follow-up questions
- Fallback chain preserved: Ollama → Gemini → OpenRouter

**UI**:

- Full-page chat interface at `/ai-assistant` with conversation sidebar
- Floating assistant button on every authenticated page (bottom-right) opening a slide-in chat panel
- Markdown rendering (headings, bold, bullets, code blocks)
- User/AI avatars, typing indicator with animated dots
- Quick prompt buttons for common questions
- Mobile responsive (slide-in sheet on mobile, sidebar on desktop)

**Database Tables**:

- `ai_conversations`: id, user_id, title, created_at, updated_at (owner-scoped RLS)
- `ai_messages`: id, conversation_id, role (user/assistant/system), content, created_at (RLS via parent conversation ownership)
- Auto-updates `ai_conversations.updated_at` via trigger when messages are inserted

**System Prompt**: Dedicated career mentor persona — professional, supportive, personalized, Nepal salary context (NPR/Rs. only).

### 21. Salary Currency (NPR)

All salary displays across the app use Nepalese Rupees (NPR / Rs.) format:

- Job cards: `Rs. 50,000+`
- Job detail: `Rs. 50,000 – Rs. 80,000`
- Database default: `salary_currency` defaults to `'NPR'`
- AI responses: system prompt instructs NPR-only formatting

### 22. Support Email Notifications

**Files**: `src/routes/support.tsx`, `src/routes/contact.tsx`, `supabase/functions/send-email/index.ts`

- Support tickets: admin email notification on new ticket submission
- Contact form: saves to `contact_messages` table + sends admin email notification
- Both use the existing `send-email` edge function (Resend API)
- Fire-and-forget pattern — email failures don't break the form submission

### 23. Resume Scan → Profile Auto-Update

**Files**: `src/lib/ai.service.ts` (`scanResumeFromStorage`)

After AI resume scanning:

- Extracted skills saved to `profiles.ai_profile_data` JSONB column
- If user has no skills set, extracted skills auto-populate `profiles.skills`
- Full AI insights (summary, strengths, keywords, missing skills) stored for admin viewing
- Users can edit AI-generated information later via profile editor

## Feature Flows

### 1. Job CRUD (Employer)

**Create Job** (`/employer/jobs/new`):

1. Employer must have a company profile first
2. Fill in title, description, requirements, responsibilities, benefits, skills, location, salary, job type, experience level
3. Job is created with `status: 'active'`
4. Redirected to job applicants page

**Edit/Delete/Publish/Close**:

- Employer can update job fields via the employer dashboard
- Job status can be toggled between `active`, `closed`, `draft`, `paused`
- Deleting a job cascades to applications and interview records

**Routes**:

- `/employer/jobs/new` — Create job
- `/employer/jobs/$jobId` — View applicants for a job
- `/employer` — Employer dashboard with job list

### 2. Application Workflow

**Status Flow**:

```
Applied → Viewed → Reviewing → Shortlisted → Interview Scheduled → Interview Completed → Selected
                    ↓                                                                    ↓
                 Rejected                                                              Offer
                    ↓
                 Withdrawn
```

**How it works**:

1. **Job seeker applies** (`ApplyJobDialog`): Submits cover letter + optional resume. Application created with `status: 'applied'`. An `application_events` row is created. Notification sent to employer.
2. **Employer reviews** (`/employer/jobs/$jobId`): Views all applicants, can change status via dropdown. Each status change:
   - Updates `applications.status`
   - Creates an `application_events` row with event type and timestamp
   - Creates a `notifications` row for the job seeker
3. **Job seeker tracks** (`/applications`): Views all applications with a timeline of events showing each status change.

**Status Values and Meanings**:

| Status                              | Meaning                                |
| ----------------------------------- | -------------------------------------- |
| `applied`                           | Initial application submitted          |
| `viewed`                            | Employer opened/viewed the application |
| `reviewing`                         | Employer is actively reviewing         |
| `shortlisted`                       | Passed initial screening               |
| `interview` / `interview_scheduled` | Interview has been scheduled           |
| `interview_completed`               | Interview finished, awaiting decision  |
| `selected`                          | Candidate selected for the role        |
| `rejected`                          | Candidate not selected                 |
| `offer`                             | Job offer extended                     |
| `withdrawn`                         | Candidate withdrew application         |

### 3. Interview Workflow

**Scheduling** (`ScheduleInterviewDialog`):

1. Employer clicks "Schedule" on an applicant card
2. Dialog checks Google Calendar connection status
3. If not connected: Employer connects Google account via OAuth popup
   - OAuth flow: `startGoogleCalendarConnect` → Google consent → `saveGoogleCalendarConnection`
   - Refresh token stored encrypted in `app_user_connections`
4. If connected: Employer enters title, start time, duration
5. `scheduleInterview` server function:
   - Creates Google Calendar event with `conferenceData` (auto-generates Meet link)
   - Sends email invitation to candidate via Google Calendar (`sendUpdates: all`)
   - Saves event to `interview_events` table with `meet_link`, `google_event_id`
   - Creates a notification for the candidate
6. Meet link is copied to clipboard for sharing

**Candidate Accept/Decline**:

- Candidate sees interview notification in dashboard and notifications page
- Interview record includes `accepted_at` / `declined_at` timestamps
- Both employer and candidate can see interview status

**Dashboard Display**:

- Employer dashboard: Shows upcoming interviews with candidate name, date, Meet link
- Candidate dashboard: Shows scheduled interviews with employer info and Meet link

**Email Invitation**:

- Google Calendar automatically sends email invitation to candidate
- Additional email notifications sent via `send-email` edge function for:
  - Interview scheduled
  - Interview reminder (can be configured)
  - Interview cancelled

### 5. Real-Time Messaging

**Architecture**:

- `chats` table: Stores 1:1 conversation threads between `user_a` and `user_b`
- `messages` table: Individual messages with `sender_id`, `receiver_id`, `chat_id`, `body`, `is_read`, `read_at`
- Real-time via Supabase Realtime channels

**Flow**:

1. **Start conversation**: Employer clicks message icon on applicant card → navigates to `/messages?with={userId}`
2. **Chat list**: Left panel shows all conversations with latest message preview and unread count
3. **Active chat**: Right panel shows message history with real-time updates
4. **Send message**: Type and send — message inserted into `messages` table, triggers real-time event
5. **Read receipts**: Messages marked as `is_read: true` when viewed by recipient
6. **Notifications**: New message creates a notification for the recipient

**Real-time subscription**:

```typescript
supabase
  .channel("messages")
  .on("postgres_changes", { event: "INSERT", schema: "public", table: "messages" }, handler)
  .subscribe();
```

### 6. Blog CRUD

**Routes**:

- `/blog` — Public blog listing (published posts only)
- `/blog/$slug` — Individual blog post
- `/blog-editor` — Author's blog management

**Create/Edit** (`/blog-editor`):

1. Author creates new post with title, slug, excerpt, content (markdown), cover image, tags, published flag
2. Save: Insert or update in `blogs` table
3. Publish: Set `published: true` and `published_at: now()`
4. Draft: `published: false` — only visible to author

**Delete**: Author can delete their own posts; admins can delete any post

### 7. Community Posts CRUD

**Feed** (`/feed`):

1. **Create post**: Text content + optional image upload (stored in Supabase Storage `posts` bucket)
2. **View feed**: All posts ordered by `created_at DESC` with author info, likes count, comments count
3. **Like**: Toggle like on any post (insert/delete in `post_likes`)
4. **Save**: Bookmark posts (insert/delete in `post_saves`)
5. **Comment**: Add comment to any post (insert in `post_comments` with `content`)
6. **Reply**: Comments support `parent_id` for threaded replies
7. **Edit/Delete**: Authors can edit/delete their own posts and comments
8. **Report**: Users can report posts for moderation (insert in `post_reports`)
9. **Pagination**: Load 50 posts at a time with infinite scroll capability
10. **Real-time**: New posts and likes update via Supabase Realtime channels

**Triggers**:

- `post_comments_count_trigger`: Updates `posts.comments_count` on comment insert/delete
- `post_likes_count_trigger`: Updates `posts.likes_count` on like insert/delete

**Route**: `/admin` (requires `admin` role)

**Analytics**:

- Total users, jobs, applications, companies count cards
- Real-time stats via `supabase.from('table').select('*', { count: 'exact', head: true })`

**User Management**:

- View all users with their roles (joined from `profiles` + `user_roles`)
- Promote/demote roles: Update `user_roles.role` between `job_seeker`, `employer`, `admin`
- Suspend/delete users

**Job Management**:

- View all jobs with company name and application count
- Activate/close jobs (toggle `status` between `active` and `closed`)

**Company Management**:

- View all companies
- Verify companies (set `is_verified: true` or `verification_status: 'verified'`)
- Suspend/delete companies

**Blog Management**:

- View, edit, delete any blog post

**Support Tickets**:

- View all support tickets
- Reply to tickets (update `admin_reply` and `status`)
- Mark as resolved/in_progress

**Content Moderation**:

- View reported posts (`post_reports` and `reports` tables)
- Review and action reports (update `status` to `reviewed`, `actioned`, or `dismissed`)
- Delete reported content if necessary

### 9. Assessment Flow

**Routes**:

- `/assessments` — Assessment list and taking interface

**Create/Edit/Delete** (Admin/Employer):

1. Create assessment with title, description, category, difficulty, duration, passing score
2. Add questions as JSON array: `[{ question, options: [], correct_answer, points }]`
3. Set `is_active: true` to publish
4. Edit: Update fields and questions
5. Delete: Remove assessment (cascades to attempts)

**Take Assessment** (Job Seeker):

1. View available assessments on dashboard
2. Click "Take assessment" → questions displayed without correct answers
3. Select answers for each question
4. Submit: Calls `submit_assessment` RPC function
   - Validates answers against `correct_answer` field
   - Computes score as `(correct / total) * 100`
   - Checks against `passing_score` (default 70)
   - Records attempt in `assessment_attempts` with `score`, `passed`, `answers`, `completed_at`

**Scoring**:

- Score = percentage of correct answers
- Pass/Fail = score >= passing_score
- Attempt history visible to user and admin

### 10. Notifications System

**Table**: `notifications` (columns: `user_id`, `type`, `title`, `message`, `link`, `metadata`, `is_read`, `created_at`)

**Types**:

| Type          | Trigger                                  |
| ------------- | ---------------------------------------- |
| `application` | Application status changed               |
| `interview`   | Interview scheduled/cancelled            |
| `message`     | New message received                     |
| `assessment`  | Assessment assigned/completed            |
| `admin`       | Admin action (role change, verification) |
| `job`         | New job matching preferences             |
| `system`      | System announcements                     |

**Flow**:

1. Event occurs (e.g., application status change)
2. `create_notification()` RPC inserts a row
3. User sees unread badge in header
4. Notifications page shows all notifications with timestamps
5. Click marks as read (`is_read: true`)
6. "Mark all read" button bulk updates

**Real-time**: Notifications update via Supabase Realtime subscription on the `notifications` table
