# Jagire — AI-Powered Job Portal

A full-featured AI-powered job portal built with **React 19 + TypeScript + TanStack Router + React Query + Tailwind CSS v4 + Supabase**. Supports job seekers, employers, and admins with real-time messaging, interview scheduling, AI resume scoring, community feed, blogging, assessments, and more.

## Tech Stack

- **Frontend**: React 19, TanStack Router (file-based), React Query, Tailwind CSS v4, shadcn/ui (New York), lucide-react icons
- **Backend**: Supabase (PostgreSQL, Auth, Realtime, Storage, Edge Functions)
- **AI**: Google Gemini (REST) for resume scoring, career recommendations, learning suggestions, LinkedIn/GitHub import
- **Calendar**: Google Calendar API (OAuth) for interview scheduling with auto-generated Meet links
- **Email**: Resend via `send-email` Edge Function
- **Payments**: eSewa v2 (ePay) test mode
- **PDF**: html2pdf.js, jsPDF
- **Build**: Vite 8 + TanStack Start (SSR)

## Feature Flows

### 1. Authentication

**File**: `src/routes/auth.tsx`, `src/hooks/use-auth.tsx`, `src/integrations/supabase/client.ts`

1. Sign up (email/password) or Google OAuth at `/auth`
2. `supabase.auth.signUp` → triggers `handle_new_user` DB trigger (creates `profiles` + `user_roles` row with default `job_seeker` role)
3. `onAuthStateChange` in `AuthProvider` updates session; role fetched from `user_roles` table (deferred to avoid deadlock)
4. Role drives dashboard redirect: `admin` → `/admin`, `employer` → `/employer`, else `/dashboard`
5. Referral codes captured via `?ref=` query param, stored in `referrals` table

### 2. Job CRUD (Employer)

**Files**: `src/routes/_authenticated.employer.jobs.new.tsx`, `src/routes/_authenticated.employer.jobs.$jobId.tsx`, `src/routes/_authenticated.employer.index.tsx`

**Create Job** (`/employer/jobs/new`):
1. Employer must have a company profile first (`/employer/company`)
2. Fill title, description, requirements, responsibilities, benefits, skills, location, salary, job type, experience level
3. Job created with `status: 'active'`, unique slug auto-generated
4. Redirect to `/employer/jobs/$jobId` (applicants page)

**Manage**:
- Employer dashboard (`/employer`) lists all jobs with applicant counts and views
- Job applicants page: change application status via dropdown, view resume (signed URL), message candidate, schedule interview
- Admin panel can activate/close any job

### 3. Application Workflow

**Files**: `src/components/apply-job-dialog.tsx`, `src/routes/_authenticated.employer.jobs.$jobId.tsx`, `src/routes/_authenticated.applications.tsx`

**Status Flow**:
```
applied → viewed → reviewing → shortlisted → interview → interview_scheduled → interview_completed → selected
                     ↓                                                          ↓
                  rejected                                                   offer
                     ↓
                  withdrawn
```

1. **Job seeker applies** (`ApplyJobDialog`): selects/ uploads resume + cover letter → inserts `applications` row (`status: 'applied'`)
2. **Employer reviews** (`/employer/jobs/$jobId`): dropdown changes status → updates `applications.status`, inserts `application_events` row, creates notification for seeker
3. **Job seeker tracks** (`/applications`): sees all applications with event timeline (each status change with timestamp)

### 4. Interview Workflow

**Files**: `src/components/schedule-interview-dialog.tsx`, `src/lib/google-calendar.functions.ts`, `src/lib/connection-key-crypto.server.ts`

1. Employer clicks "Schedule" on applicant card → `ScheduleInterviewDialog` opens
2. Dialog checks Google Calendar connection (`getGoogleCalendarStatus` server fn)
3. If not connected: OAuth popup flow
   - `startGoogleCalendarConnect` → Google consent → `/google-calendar/callback` posts code to opener
   - `saveGoogleCalendarConnection` exchanges code for refresh token → AES-256-GCM encrypted → stored in `app_user_connections`
4. If connected: employer enters title, start time, duration
5. `scheduleInterview` server fn:
   - Refreshes access token via refresh token
   - Creates Google Calendar event with `conferenceData` (auto Meet link)
   - Sends email invite to candidate (`sendUpdates: all`)
   - Inserts `interview_events` row with `meet_link`, `google_event_id`
   - Meet link copied to clipboard
6. Candidate sees notification + interview on dashboard

### 5. AI Resume Scanner

**Files**: `src/routes/_authenticated.resume-scanner.tsx`, `src/lib/ai.functions.ts`, `src/integrations/gemini/server.ts`

1. Upload PDF/DOCX resume → stored in `resumes` Supabase Storage bucket
2. `scanResumeFromStorage` server fn:
   - Downloads file via service-role client
   - Extracts text (mammoth for DOCX, unpdf for PDF)
   - Calls Gemini with ATS-reviewer system prompt → returns JSON scores
   - Updates `resumes` row with `overall_score`, `ats_score`, `grammar_score`, `formatting_score`, `keyword_score`, `professionalism_score`, `suggestions`, `parsed_data` (summary + skills)
3. Matches extracted skills against active jobs' `required_skills` → returns top 8 job matches with fit %
4. Results displayed with progress bars + suggestion list + job match cards

### 6. AI Career Recommendations

**Files**: `src/routes/_authenticated.career.tsx`, `src/lib/ai.functions.ts`

1. `careerRecommendations` server fn fetches user profile + default resume skills
2. Gemini returns JSON: `career_paths` (title, why, next_steps), `skill_gaps`, `recommended_certifications` (name, provider), `suggested_search_keywords`
3. Rendered as cards with career paths, skill gap badges, cert list, search keyword chips

### 7. AI Learning Center

**Files**: `src/routes/_authenticated.learn.tsx`, `src/lib/ai.functions.ts`

1. `learningRecommendations` server fn uses profile skills + headline
2. Gemini suggests 8 mixed resources (courses, videos, challenges, interview prep) with URLs, providers, skills
3. Mark complete → inserts `learning_items` + `learning_progress` + awards `badges`
4. Progress bar + badge display

### 8. Profile Import (GitHub + LinkedIn)

**Files**: `src/routes/_authenticated.profile.tsx`, `src/lib/ai.functions.ts`

**GitHub** (`importFromGitHub`): fetches GitHub user + starred repos via REST API → extracts projects (name, description, URL, stars, language), skills (unique languages), updates profile (full_name, bio, location, website, avatar)

**LinkedIn** (`importFromLinkedInText`): user pastes LinkedIn About/Experience text → Gemini extracts structured profile (full_name, headline, about, location, current_position, experience_years, skills) → updates profile

### 9. Real-Time Messaging

**Files**: `src/routes/_authenticated.messages.tsx`

1. Start: employer clicks message icon on applicant card → `/messages?with={userId}`
2. `useEffect` ensures chat exists (creates if needed, sorted `user_a`/`user_b`)
3. Left panel: chat list ordered by `last_message_at`
4. Right panel: message history, real-time via Supabase Realtime channel `chat:{id}` on `messages` INSERT
5. Send: insert into `messages`, update `chats.last_message_at`
6. Auto-scroll to bottom on new messages

### 10. Community Feed

**Files**: `src/routes/_authenticated.feed.tsx`

1. Create post: text + optional image upload (Supabase Storage `posts` bucket, 5MB limit, signed URL)
2. Feed: 50 posts ordered by `created_at DESC` with author info, likes/comments counts
3. Like: toggle in `post_likes` (optimistic via React Query invalidation)
4. Save: toggle in `post_saves`
5. comment: insert into `post_comments`
6. Realtime: channel `feed` on `posts` + `post_likes` changes → invalidates `feed` query
7. Share: native share API or clipboard fallback

### 11. Blog

**Files**: `src/routes/blog.index.tsx`, `src/routes/blog.$slug.tsx`, `src/routes/_authenticated.blog-editor.tsx`

- `/blog`: published posts only (RLS-enforced), cover image, tags, excerpt
- `/blog/$slug`: full post with cover, tags, publish date, markdown content
- `/blog-editor`: author CRUD (create, edit, delete, publish/draft toggle), slug auto-generated from title

### 12. Assessments

**Files**: `src/routes/_authenticated.assessments.tsx`

- Admin can create assessments (title, category, difficulty, description, questions as JSON, passing score, duration)
- Job seeker takes assessment: questions rendered without correct answers, radio selection
- Submit: client computes score (`correct/total * 100`), inserts `assessment_attempts` with answers + score
- Best score + pass/fail badge shown on assessment card

### 13. Admin Panel

**Files**: `src/routes/_authenticated.admin.tsx`

- Stats cards: users, jobs, applications, companies (exact count, head-only queries)
- Tabs: Users (list + role badges), Jobs (activate/close toggle), Companies (view link), Tickets (reply + resolve)
- Role guard: only `admin` role sees content; others see access-denied card

### 14. Notifications

**Files**: `src/routes/_authenticated.notifications.tsx`, `src/components/layout/site-header.tsx`

- Header bell shows unread count badge (query `notif-unread`)
- Realtime: channel `notif:{userId}` on `notifications` table → invalidates unread + list queries
- Notifications page: marks all as read on view, individual mark-read button
- Types: application, interview, message, assessment, admin, job, system

### 15. Companies & Reviews

**Files**: `src/routes/companies.index.tsx`, `src/routes/companies.$slug.tsx`

- Directory: all companies with logo, industry, tagline
- Detail: company info (mission, vision, culture, hiring process, benefits, technologies), open positions, reviews
- Reviews: star rating + title + body; company owner can reply (inserts `review_replies`)
- Average rating computed client-side

### 16. Resume Builder

**Files**: `src/routes/_authenticated.resume-builder.tsx`

- Multiple resumes per user (saved to `resumes.resume_data` JSONB)
- Sections: experience, education, skills, projects (add/remove items)
- Templates: modern, classic, minimal
- Live preview + PDF export via html2pdf.js (with oklch→hex color fix on clone)

### 17. Referrals

**Files**: `src/routes/_authenticated.referrals.tsx`

- Unique referral code on profile (DB trigger generates on signup)
- Shareable link: `/auth?ref={code}`
- Invite by email: inserts `referrals` row (status pending)
- Track referral status + reward credits

### 18. Payments (eSewa)

**Files**: `src/routes/checkout.$plan.tsx`, `src/routes/pricing.tsx`

- eSewa v2 ePay test mode (merchant `EPAYTEST`)
- HMAC-SHA256 signature over signed fields (total_amount, transaction_uuid, product_code)
- Plans: Starter (Rs. 4,900), Pro (Rs. 9,900)
- Success/failure redirect pages

### Enums

- **`app_role`**: `job_seeker`, `seeker`, `employer`, `admin`
- **`application_status`**: `applied`, `viewed`, `reviewing`, `shortlisted`, `interview`, `interview_scheduled`, `interview_completed`, `selected`, `rejected`, `offer`, `withdrawn`
- **`job_status`**: `draft`, `published`, `closed`, `active`, `paused`
- **`job_type`**: `full_time`, `part_time`, `contract`, `internship`, `remote`, `freelance`
- **`experience_level`**: `entry`, `junior`, `mid`, `senior`, `lead`, `executive`

### RPC Functions

| Function | Purpose |
|----------|---------|
| `get_user_role(user_id)` | Returns the role for a user |
| `has_role(user_id, role)` | Checks if user has a specific role |
| `submit_assessment(assessment_id, answers)` | Validates answers, computes score, records attempt |
| `get_assessment_questions(assessment_id)` | Returns questions without correct answers |
| `create_notification(user_id, type, title, message, link, metadata)` | Creates a notification |
| `get_or_create_chat(user_a, user_b)` | Returns existing or creates new chat between users |
| `update_application_status(application_id, new_status, actor_id, note)` | Updates status, creates event + notification |

### RLS (Row Level Security)

All tables have RLS enabled with ownership-based policies:
- Users can only CRUD their own data (resumes, profiles, posts, etc.)
- Public data (jobs, companies, blogs, posts) readable by all authenticated users
- Admin role (`has_role(auth.uid(), 'admin')`) gets elevated access
- Application events visible to both seeker and employer
- Messages visible to both chat participants

## Edge Functions

### `send-email` — `supabase/functions/send-email/index.ts`

Sends transactional emails via Resend API.

**Endpoint**: `POST /functions/send-email`

**Request body**:
```json
{
  "to": "user@example.com",
  "subject": "Email subject",
  "html": "<h1>HTML content</h1>",
  "text": "Plain text fallback"
}
```

**Required secret**: `RESEND_API_KEY`

**CORS**: All responses include the standard CORS header set.

**Triggered for**:
| Event | Recipient | Content |
|-------|-----------|---------|
| Application received | Employer | New application for {job title} from {candidate} |
| Application status changed | Job seeker | Your application status is now {status} |
| Shortlisted | Job seeker | You've been shortlisted for {job title} |
| Interview scheduled | Job seeker | Interview scheduled for {date} — Meet link: {link} |
| Selected | Job seeker | Congratulations! You've been selected for {job title} |
| Rejected | Job seeker | Update on your application for {job title} |
| Job offer | Job seeker | Job offer for {job title} |
| New message | Recipient | New message from {sender} |
| Assessment assigned | Job seeker | New assessment: {assessment title} |

## Setup & Build

### Prerequisites

- Node.js 20+, Bun (or npm/pnpm)
- Supabase project linked (already provisioned)

### Install

```bash
npm install
```

### Development

The dev server runs automatically in this environment. Do NOT run `npm run dev` manually.

### Build

```bash
npm run build
```

Build uses Vite + TanStack Start with SSR. The server entry is overridden to `src/server.ts` for error-page fallback handling.

```bash
npm run lint
npm run format
```

Required buckets (create in Supabase Dashboard if missing):
- `resumes` — resume uploads
- `posts` — feed post images

### Auth Configuration

- Email/password enabled
- Email confirmation OFF
- Google OAuth provider configured (for sign-in + Calendar)
